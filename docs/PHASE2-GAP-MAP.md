Date: 2026-08-18

This document records the inspection baseline before Phase 2 implementation. It is a migration map, not a substitute for executable tests or the progress ledger.

## Migration constraints

- Existing schema-version-1 workflows remain valid and receive deterministic defaults (`version: 1`, `lifecycle: ENABLED`).
- Existing entity and event repositories remain the persistence boundary. New immutable records use distinct entity kinds and optimistic concurrency.
- Running definitions are never reloaded by ID. A run stores the exact content digest and all referenced asset versions.
- Provider session IDs may be retained as hints, but replay always starts from the workflow checkpoint, execution specification, authoritative work item, and repository checkpoint.
- Side-effect-free evaluation receives read-only resolvers. It cannot claim work, mutate a provider, execute tools, or write persistence.
