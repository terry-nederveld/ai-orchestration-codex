# Context

Workflows need sequential and parallel steps, conditions, retries, bounded loops, approvals, composition, variables, outputs, and terminal transitions without compiling behavior into the application.

# Decision

Use repository-versioned `.fable/workflow.yaml` files validated against a versioned JSON Schema. Compile each document into an acyclic dependency graph plus explicit bounded loop edges. Execute ready steps concurrently within budget limits through a registry of step handlers.

# Rationale

YAML is approachable for users, JSON Schema supports editors, and a compiled graph makes dependencies, readiness, cycle rejection, and recovery deterministic. Registered handlers keep action behavior composable.

# Alternatives Considered

- Imperative scripts are flexible but difficult to validate, visualize, resume, and secure.
- A linear step list cannot express parallel review and test stages cleanly.
- A general-purpose workflow dependency would add a large execution model and deployment footprint.

# Consequences

The expression language must remain deliberately small and safe. Schema evolution requires explicit versions. Loop safeguards are mandatory and arbitrary code in conditions is forbidden.

# Implementation Notes

Resolve configuration in the order defaults, user, project, workflow, run. Environment variables are resolved only for explicit secret references. Persist step attempts and outputs after every terminal step state.
