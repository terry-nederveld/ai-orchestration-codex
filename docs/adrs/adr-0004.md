# Context

Connections, projects, workflows, claims, runs, sessions, usage, artifacts, and events must survive restarts. Local operation should have no external database dependency, while repositories must remain replaceable.

# Decision

Use SQLite in WAL mode behind repository interfaces. Store current aggregate snapshots for efficient reads and append immutable structured events in the same transaction where state changes. Apply numbered forward-only SQL migrations at startup.

# Rationale

SQLite is durable, portable, transactional, inspectable, and appropriate for a single-machine control plane. An event log provides observability and recovery evidence without requiring full event sourcing.

# Alternatives Considered

- JSON files are simple but weak under concurrent updates and migrations.
- Full event sourcing adds projection and versioning complexity beyond current needs.
- PostgreSQL would impose an external service on individual users.

# Consequences

The first implementation is single-writer oriented and must use busy timeouts and short transactions. Domain code remains database-neutral. Server deployments can replace repository implementations later.

# Implementation Notes

Do not store secret values in SQLite. Enable foreign keys and WAL. Test every migration from an empty database and from the prior schema version.
