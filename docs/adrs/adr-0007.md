# Context

Work items, repositories, model output, extensions, and MCP servers are untrusted inputs. Agents can request filesystem, process, network, source-control, and work-system mutations. Secrets must not enter model context or logs.

# Decision

Evaluate typed capabilities through a deny-by-default policy engine immediately before every side effect. Scope filesystem operations to canonical workspace roots, execute processes without a shell by default, pass secret references directly to adapters, redact structured logs, and isolate extension/MCP permissions from workflow declarations. Use OS-backed or Stronghold credential storage with an encrypted fallback.

# Rationale

Checks at the execution boundary cannot be bypassed by prompt injection or an incorrectly composed workflow. Typed capabilities are auditable and support `allow`, `deny`, `ask`, and `sandbox-only` decisions.

# Alternatives Considered

- Prompt-only safety is not an enforceable security boundary.
- Broad process-level trust makes a renderer or extension compromise catastrophic.
- Injecting secrets as environment-wide variables exposes them to unrelated subprocesses.

# Consequences

Some actions pause for approval. Provider and tool authors must declare precise permissions. Native operating-system sandboxing varies, so policy enforcement does not claim to be a complete containment boundary.

# Implementation Notes

Reject traversal after resolving symlinks, use argument arrays instead of interpolated shell commands, cap output, time, and process trees, and never return raw credentials to agent messages. Bind the control plane to loopback with an ephemeral bearer token.
